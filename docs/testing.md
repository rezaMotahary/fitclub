# تست‌نویسی — قانون الزامی

آخرین به‌روزرسانی: 2026-10-08

---

## قانون اصلی

هر فیچر و هر قابلیتی که در پروژه پیاده می‌شود **باید** برایش تست نوشته شود.

کیفیت تست‌نویسی باید **خیلی بالا** باشد و بخش‌های مهم را خوب پوشش دهد — نه تست سطحی و نمایشی.

بعد از هر **تغییر مهم**:

1. تست‌های مرتبط (و در صورت امکان کل سوئیت) اجرا شوند
2. تأیید شود که تست‌ها سبز و درست کار می‌کنند
3. به مالک پروژه **گزارش کوتاه** داده شود که تست‌ها اجرا شده‌اند و نتیجه موفق بوده (یا اگر شکست خورده، چه چیزی خراب است — بدون درگیر کردن او در جزئیات فنی پیچیده)

---

## دامنه پوشش (چه چیزهایی باید تست شوند)

### بک‌اند (`api/`)

- قوانین کسب‌وکار حیاتی: سقف هفتگی، انقضای اشتراک، بدهی، اجازه ورود/خروج
- APIها و کنترلرها (ورودی معتبر / نامعتبر)
- Auth و دسترسی نقش‌ها (member / secretary / admin)
- سرویس‌های دامنه (members, subscriptions, attendance, payments)

### فرانت‌اند (`web/`)

- رفتارهای مهم UI به‌صورت تست واحد/کامپوننت یا e2e برای جریان‌های کلیدی
- حداقل جریان‌های حیاتی: ورود منشی و ثبت حضور، مشاهده وضعیت توسط عضو، کارهای ادمین حساس

### اولویت تست

1. منطق حضور و قوانین رد ورود (بالاترین اولویت)
2. اشتراک / پلن / مالی
3. Auth و RBAC
4. بقیهٔ فیچرها همراه با همان فیچر

## زمان اجرا

| موقعیت | الزام |
|--------|--------|
| پیاده‌سازی فیچر جدید | همزمان با فیچر، تست هم اضافه شود |
| تغییر مهم در منطق موجود | تست‌های مربوط به‌روز + اجرا |
| قبل از push به GitHub بعد از تغییر مهم | تست‌ها باید سبز باشند |
| باگ‌فیکس | تستی که باگ را می‌گیرد (regression) اضافه شود |

«تغییر مهم» یعنی: فیچر جدید، تغییر قانون کسب‌وکار، تغییر API، تغییر مدل داده، یا هر چیزی که رفتار کاربر را عوض کند. اصلاح متن docs به‌تنهایی تست اجباری ندارد مگر منطق را تغییر دهد.

---

## ابزارها (هم‌راستا با استک)

| لایه | ابزار فعلی / هدف |
|------|------------------|
| API | Vitest (از قبل در Nest scaffold هست) + تست e2e سوپرتست |
| Web | در سشن‌های بعدی: تست واحد/کامپوننت (مثلاً Vitest + Testing Library) و در صورت نیاز Playwright برای جریان‌های حیاتی |

جزئیات فنی ابزار را عامل انتخاب و نگه‌داری می‌کند؛ مالک درگیر انتخاب فریم‌ورک تست نمی‌شود.

---

## گزارش به مالک

بعد از هر تغییر مهم، یک گزارش کوتاه شبیه این کافی است:

> تست‌ها اجرا شد: API ✅ / Web ✅ (یا اگر بخشی هنوز سوئیت ندارد، صریح بگو). همه سبز بودند.

اگر تست قرمز بود: تا سبز نشود push نکن (مگر مالک صریحاً خلافش را بخواهد). مشکل را خودت درست کن.
