# مسیر آپدیت سرور — فیت‌کلاب

آخرین به‌روزرسانی: 2026-11-01  
نسخه: `0.16.0`

این صفحه برای عامل است. مالک ترمینال نمی‌زند. دامنه و شرکت هاست هنوز از مالک گرفته نشده؛ حدس نزن. تا آن دسترسی برسد، سایت روی اینترنت بالا نمی‌آید. اسکریپت‌های ایمنی آماده‌اند.

قانون داده: `docs/production-data.md` · امنیت: `docs/security.md`

---

## قانون این مسیر

- قبل از هر آپدیت، یک پشتیبان از دیتابیس بگیر.
- بعد از گرفتن کد تازه: `prisma migrate deploy` (جدول و ستون جدید). **نه** `migrate reset`.
- **هرگز** `npx prisma db seed` روی سرور. `DEMO_MODE=true` هم این قفل را باز نمی‌کند.
- بار اول، اگر دیتابیس خالی است: `npm run bootstrap:server` داخل `api/`. این دستور چیزی را پاک نمی‌کند. بار دوم هم بی‌خطر است؛ حساب موجود و رمزش دست نمی‌خورد و تعداد اعضا کم نمی‌شود.
- لینک مخفی منشی و مدیر فقط در env سرور می‌ماند. در گیت نوشته نمی‌شود.

## چک‌لیست env سرور آموزشی

فایل‌های env روی سرور ساخته می‌شوند و commit نمی‌شوند. این سرور تستی/آموزشی است (`DEMO_MODE`). باشگاه واقعی بعداً این دو کلید دمو را برمی‌دارد و پیامک را روشن می‌کند.

### API — `api/.env`

| کلید | مقدار این سرور |
|------|----------------|
| `NODE_ENV` | `production` |
| `DEMO_MODE` | `true` |
| `OTP_DEV_CODE` | `123456` |
| `KAVENEGAR_ENABLED` | `false` |
| `WEB_ORIGIN` | `https://` به‌اضافهٔ دامنه‌ای که مالک می‌دهد |
| `DATABASE_URL` | پستگرس جدا با رمز طولانی تصادفی. `fitsteel_dev` ممنوع |
| `TRUST_PROXY` | `1` (پشت پروکسی https) |
| `PORT` | `3001` — این پورت و پورت دیتابیس از اینترنت بسته باشند |

### وب — `web/.env.local` قبل از build

| کلید | مقدار این سرور |
|------|----------------|
| `NEXT_PUBLIC_DEMO_MODE` | `true` |
| `NEXT_PUBLIC_SITE_URL` | `https://` همان دامنه |
| `NEXT_PUBLIC_API_URL` | آدرس https که به API می‌رسد (معمولاً همان دامنه با `/api`) |
| `STAFF_PATH_SECRETARY` | رشتهٔ تازه، حداقل ۳۲ حرف، فقط `A-Z a-z 0-9 _ -`، بدون واژهٔ admin / secretary / staff / fitclub |
| `STAFF_PATH_ADMIN` | یک رشتهٔ دیگر، متفاوت از منشی |

این دو مسیر را در داک و گیت ننویس. اگر مالک باید لینک را ببیند، فقط در پیام خصوصی.

بعد از بالا آمدن روی این سرور آموزشی: `/how-to-open` باز باشد، ورود عضو با `123456` کار کند، و آدرس‌های کوتاه `/admin` و `/secretary` صفحهٔ «پیدا نشد» باشند. محدودیت تعداد تلاش کد ورود همان می‌ماند.

## بار اول

1. دیتابیس پستگرس با رمز قوی. اگر واقعاً خالی است، بکاپِ قبل از ساخت لازم نیست؛ از همین لحظه به بعد قبل از هر آپدیت بکاپ بگیر.
2. envهای بالا را بگذار.
3. داخل `api/`: `npx prisma migrate deploy`
4. داخل `api/`: `npm run bootstrap:server`
5. وب را با همان env بساز و هر دو را پشت https روشن کن.
6. یک بکاپ بگیر و پوشهٔ نگهداری را یادداشت کن.

`bootstrap:server` فقط اگر نباشند این‌ها را اضافه می‌کند:

- چهار تعرفهٔ شروع (۲، ۳، ۴، و هر روز). اگر تعرفه‌ای با همان تعداد روز باشد، قیمتش عوض نمی‌شود.
- یک مدیر: `admin@fitclub.local`
- یک منشی: `secretary@fitclub.local`
- یک عضو تست: موبایل `09121234567`، کد عضویت `FS-1001`، بدون بدهی و بدون سابقه. اگر این شماره از قبل باشد، همان حساب می‌ماند.

رمز مدیر و منشی همان رمز آموزشی صفحهٔ راهنماست. اگر مالک رمز جدا خواست، با `npm run staff:set` عوض می‌شود؛ bootstrap رمز موجود را دوباره نمی‌نویسد.

## هر آپدیت

به همین ترتیب:

1. پشتیبان دیتابیس (`npm run backup:db` داخل `api/`)
2. `git pull --ff-only`
3. `npm ci` در `api/` و `web/`
4. داخل `api/`: `npx prisma migrate deploy`
5. build در `api/` و `web/`
6. همان سرویس API و وب را که از قبل روی سرور روشن است دوباره راه بینداز. اسم سرویس را حدس نزن.

اسکریپت همین ترتیب را انجام می‌دهد و فقط وقتی `FITCLUB_SERVER_UPDATE=1` باشد کار می‌کند، تا روی کامپیوتر برنامه‌نویس اشتباهی اجرا نشود:

- لینوکس: `scripts/server-update.sh`
- ویندوز: `scripts/server-update.ps1`

قبل از اجرای اسکریپت، `BACKUP_DIR` باید یک پوشهٔ مطلق بیرون از پروژه باشد. env وب باید از قبل حاضر باشد چون متن‌های عمومی سایت موقع build داخل نسخه می‌روند.

## پشتیبان روزانه

دستور، داخل `api/`:

```text
BACKUP_DIR=<پوشهٔ مطلق بیرون از پروژه> npm run backup:db
```

شکل مسیر را عامل روی خود سرور انتخاب می‌کند. نمونهٔ شکل، نه آدرس این باشگاه: `/var/backups/fitclub` یا `D:\fitclub-backups`.

خروجی فایل `fitclub-تاریخ.dump` است. سی فایل آخر می‌ماند (`FITCLUB_BACKUP_KEEP`). فقط همین فایل‌های دامپ قدیمی حذف می‌شوند؛ دادهٔ باشگاه و فایل‌های دیگر آن پوشه دست نمی‌خورند.

هر شب همان دستور را زمان‌بندی کن. قبل از هر ریلیز یک بار دیگر، حتی اگر بکاپ شب گرفته شده.

اگر آپدیت خراب شد و باید به همان بکاپ برگشت: API را خاموش کن و فایل دامپ را به دیتابیس برگردان. این کار دادهٔ جاری را با نسخهٔ بکاپ عوض می‌کند. برای آپدیت عادی از برگرداندن بکاپ استفاده نکن و دیتابیس را خالی نکن.
