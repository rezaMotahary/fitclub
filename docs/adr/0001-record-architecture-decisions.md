# ADR-0001: استفاده از ADR برای تصمیم‌های معماری

- Status: Accepted
- Date: 2026-10-08

## Context

پروژه فیت‌استیل از پروتوتایپ UI وارد فاز ساخت واقعی می‌شود. تصمیم‌های معماری (استک، مدل دسترسی، شکل محصول) باید قابل پیگیری بمانند تا بعداً دلیل هر انتخاب گم نشود.

## Decision

همهٔ تصمیم‌های معماری مهم در `docs/adr/` به‌صورت فایل‌های شماره‌دار Markdown ثبت می‌شوند. هر ADR شامل Context، Decision و Consequences است. مستندات غیرفعال‌سازی‌شده حذف نمی‌شوند؛ با وضعیت `Deprecated` یا `Superseded` علامت می‌خورند.

## Consequences

- تاریخچه rational تصمیم‌ها حفظ می‌شود.
- تغییر استک یا معماری نیاز به ADR جدید (یا supersede) دارد.
- هزینهٔ جزئی: نوشتن چند پاراگراف برای هر تصمیم مهم.
