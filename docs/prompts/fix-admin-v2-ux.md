## KI-008 — جای پیام
الان `error` و `note` سراسری بالای کل `AdminDesk` است (`web/src/components/AdminDesk.tsx` حدود ۳۱۷–۳۱۸). جستجو می‌گوید «نتیجه جستجو به‌روز شد» بالای صفحه.

رفتار درست: هر پیام تأیید/خطا **کنار همان بخش**:
- جستجوی عضو → زیر/کنار فرم جستجو
- فیلتر ماه/بازه → کنار فرم درآمد
- ذخیره قیمت پلن → کنار همان کارت تعرفه
- تخفیف تمدید → کنار همان فرم
- آرشیو/فعال‌سازی → کنار همان عضو یا لیست اعضا
- ثبت پرداخت در PaymentDesk هم اگر نوار سراسری گمراه‌کننده است، کنار همان فرم قسط/تمدید

نوار سراسری بالای صفحه برای این کارها حذف شود (خطای boot/ارتباط کل صفحه می‌تواند بالای صفحه بماند).

## KI-009 — تقویم شمسی از/تا
«از تاریخ» و «تا تاریخ» فقط input متن است. با کلیک/فوکوس یک **تقویم شمسی** باز شود (ماه/سال شمسی، انتخاب روز). مقدار قابل‌ارسال به API همان فرمت `parseJalaliDateInput`. رقم فارسی و انگلیسی اگر تایپ کمکی ماند باید کار کند. تم روشن/تاریک + RTL. تقویم میلادی ممنوع؛ از منطق جلالی موجود پروژه استفاده کن.

## KI-010 — مبلغ روی نمودار
`web/src/components/RevenueChart.tsx`: مبلغ فقط در `title` هاور است. روی/بالای هر ستون مبلغ خوانا باشد، بدون موس. تم روشن/تاریک.

## KI-011 — برچسب روزانه بریده نشود
`.admin-bar-label` ellipsis دارد. نمودار روزانه برچسب کامل و خوانا (مثلاً «۱ آبان») بدون «…». ستون‌ها روی هم نروند.

## KI-012 — قیمت سایت از تعرفه
`web/src/app/page.tsx` مبلغ هاردکد دارد. `/` باید از `GET /api/plans` بخواند. PATCH همچنان فقط مدیر. بعد از ذخیره در `/admin`، رفرش `/` عدد جدید را نشان دهد. «جلسه در ماه» روی سایت بماند. اشتراک‌های قبلی قیمت خودشان می‌مانند.

## KI-013 — ثبت پرداخت همان عضو را باز کند
در `/admin` روی علی رضایی (یا هر عضو بدهکار) «ثبت پرداخت» الان `href="/admin/payments"` بدون شناسه است. `PaymentDesk` با `pickInitialMember` فرد دیگری (اولین بدهکار) را انتخاب می‌کند.

رفتار درست:
- لینک مثلاً `/admin/payments?member=FS-1046` یا `?memberId=`
- بوت PaymentDesk اگر این پارامتر باشد همان عضو را انتخاب کند؛ وگرنه رفتار فعلی پیش‌فرض
- منشی اگر لینک مشابه داشت همین قانون
- تست: کلیک علی → صفحه پرداخت با عنوان علی؛ نه شخص دیگر

## KI-014 — صفحه‌بندی لیست‌ها
لیست اعضا، لیست پرداخت‌ها، نتایج جستجوی عضو در پرداخت، و هر لیست بلند دیگر پنل مدیر الان همه را پشت‌سرهم می‌آورد (API فقط `take`/`limit` بدون صفحه).

رفتار درست:
- صفحه‌بندی واقعی (page + pageSize، مثلاً ۲۰ ردیف)
- کنترل فارسی: قبلی / بعدی + «صفحه ۲ از ۱۰» با رقم فارسی
- API: `page`/`skip` + `total` تا تعداد صفحه معلوم باشد — `members.service` و `payments.service`
- صفحه سنگین نشود؛ چشم اذیت نشود
- جستجو از صفحهٔ ۱ شروع شود

## تست
- واحد: پارس query عضو برای پرداخت؛ صفحه‌بندی (صفحه ۲ ردیف صفحه ۱ را تکرار نکند؛ total درست)
- فارسی و انگلیسی برای مبلغ تعرفه و تاریخ
- مرورگر از صفر تا صد `/admin`: پیام کنار بخش، تقویم، نمودار خوانا، تعرفه→سایت، ثبت پرداخت علی=علی، ورق زدن اعضا و پرداخت‌ها
- regression: فیلتر ماه، KPI، تخفیف، KI-004…007 روی پرداخت
- تست‌ها سبز؛ با قرمز push نکن
