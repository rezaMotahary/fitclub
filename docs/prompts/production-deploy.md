# پرامپت — آماده کردن سرور بدون از دست رفتن داده

کپی کن و در چت برنامه‌نویس بفرست. مالک ترمینال نمی‌زند.

---

## متن پرامپت

```text
تو برنامه‌نویس فیت‌کلاب هستی. هدف: آماده کردن استقرار روی سرور طوری که داده هرگز پاک نشود، و اگر دسترسی سرور موجود است بالا آوردن نسخه.

قانون مالک (دائمی — docs/production-data.md):
- روی سرور دادهٔ فیک لوکال نباشد.
- فقط یک مدیر، یک منشی، یک عضو تست.
- هر آپدیت افزایشی است؛ هیچ‌وقت اطلاعات سرور از دست نرود.
- seed پاک‌کنندهٔ لوکال روی سرور ممنوع — حتی اگر DEMO_MODE=true باشد.
- ترمینال به مالک نده؛ خودت کار فنی را بکن. گزارش خیلی ساده.

بخوان: docs/production-data.md، docs/security.md، docs/launch.md، docs/handoff.md، docs/pwa.md، api/prisma/seed.ts (wipe دارد — روی سرور استفاده نشود)، staff:set، DEMO_MODE.

تصمیم‌های قفل مالک:
- PWA پیاده و QA شده.
- بررسی امنیت انجام شد؛ ۱۲ مورد رفع شد.
- دو استثنا برای همین سرور آموزشی: ورود عضو با کد 123456 بدون پیامک؛ /how-to-open برای همه باز با لینک و حساب تست. بقیهٔ قفل‌ها بمانند.
- محدودیت تلاش OTP همان بماند.

بساز / محکم کن:
1) اسکریپت bootstrap سرور جدا از seed لوکال:
   - هرگز deleteMany روی کل جدولهای دامنه نزند
   - اگر دیتابیس خالی است: ۴ پلن تعرفه + ۱ مدیر + ۱ منشی + ۱ عضو تست را upsert کند
   - اگر داده هست: موجود را پاک نکند؛ فقط حساب‌های گم‌شده را اضافه کند
   - با NODE_ENV=production هم برای بار اول مجاز باشد؛ بار دوم بی‌خطر
2) seed.ts همچنان فقط لوکال؛ اگر کسی روی production بدون نیت bootstrap آن را زد، نباید wipe کند (قفل سخت‌تر از DEMO_MODE)
3) مسیر آپدیت سرور: پشتیبان DB → git pull → migrate deploy (نه migrate reset) → build → restart. مستند کوتاه در docs/ برای عامل
4) پشتیبان‌گیری: حداقل اسکریپت/دستور روزانه dump پستگرس و محل نگهداری؛ قبل از هر ریلیز یک بکاپ
5) چک‌لیست env سرور از docs/security.md با DEMO_MODE مطابق آموزش + کلیدهای پرسنل تازه + https + رمز DB قوی
6) تست که bootstrap دو بار اجرا شود و تعداد اعضا کم نشود
7) commit + push؛ VERSION را اگر نقطه عطف استقرار دیدی بالا ببر
8) docs/production-data.md و launch و handoff را به‌روز کن

اگر به سرور واقعی دسترسی نداری (SSH/دامنه/رمز از مالک نیست): اسکریپت‌ها و داک را کامل کن، حدس هاست نزن، به مالک ساده بگو چه چیزهایی از او لازم است (دامنه، دسترسی سرور). اگر دسترسی داری، با احتیاط بالا بیاور و هرگز seed wipe نزن.

ممنوع: پاک کردن دیتابیس سرور، کپی seed نمایشی سارا/علی و بدهی ساختگی، پیامک اجباری روی این سرور آموزشی، لو کردن لینک پرسنل در گیت.

پایان به مالک ساده: سرور بالا آمد یا هنوز دامنه/دسترسی لازم است. ببرد QA در صورت آدرس واقعی. به PM بگوید: «آماده‌سازی سرور انجام شد» یا «منتظر دامنه/دسترسی سرور».
```
